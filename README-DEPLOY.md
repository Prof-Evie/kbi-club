# دليل نشر موقع KBI على Cloudflare ☁️

هذه الحزمة جاهزة بالكامل للنشر على **Cloudflare Workers** مع قاعدة بيانات **D1**.
كل ما تحتاجه: حاسوبك + حساب Cloudflare مجاني + اتصال إنترنت.

---

## 1) المتطلبات

| المتطلب | ملاحظات |
|---|---|
| [Node.js](https://nodejs.org) إصدار 20 أو أحدث | حمّل نسخة LTS ونصّبها ثم افتح نافذة أوامر جديدة |
| حساب Cloudflare مجاني | أنشئه من [dash.cloudflare.com/sign-up](https://dash.cloudflare.com/sign-up) |
| ملفات هذه الحزمة | فكّ ضغط الملف في مجلد ثابت على حاسوبك |

تحقق من التثبيت (اكتب في موجه الأوامر):

```bash
node -v
```

يجب أن يظهر رقم مثل `v20.x.x` أو أحدث.

---

## 2) خطوات النشر — من البداية حتى الموقع يعمل

افتح موجه الأوامر (Terminal على ماك/لينكس أو CMD/PowerShell على ويندوز)
واذهب إلى مجلد المشروع:

```bash
cd مسار-المجلد/kbi-club
```

### الخطوة 1 — تثبيت الحزم (مرة واحدة)

```bash
npm install
```

سيستغرق دقيقة أو اثنتين، وفي النهاية يولّد عميل Prisma ويرقّعه تلقائيًا للعمل على Cloudflare.

### الخطوة 2 — تسجيل الدخول إلى Cloudflare

```bash
npx wrangler login
```

ستفتح صفحة في المتصفح — اضغط **Allow** (سماح).

### الخطوة 3 — إنشاء قاعدة البيانات D1

```bash
npx wrangler d1 create kbi-db
```

ستظهر رسالة كهذه:

```
✅ Successfully created DB 'kbi-db'
database_id = "aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee"
```

**انسخ قيمة `database_id`** ثم افتح ملف `wrangler.jsonc` بمحرر نصوص
وضعها مكان `PASTE_YOUR_D1_DATABASE_ID_HERE` (السطر المعلَّم بتعليق عربي) واحفظ.

### الخطوة 4 — إنشاء جداول قاعدة البيانات على السحابة

```bash
npm run cf:d1-schema-remote
```

### الخطوة 5 — نقل البيانات الحالية (المشتركون + سجل العمليات)

```bash
npm run cf:d1-data-remote
```

> هذه الخطوة اختيارية: تنقل المشتركين الثلاثة وسجل العمليات كما هو الآن.
> إن أردت البدء بقاعدة فارغة تمامًا تجاوزها.

### الخطوة 6 — النشر! 🚀

```bash
npm run cf:deploy
```

أول مرة سيطلب منك اختيار المشروع — اضغط Enter لقبول الافتراضي.
في نهاية الأمر ستظهر الرابط المباشر لموقعك:

```
https://kbi-club.<حسابك>.workers.dev
```

افتحه وسجّل الدخول كما تعمل محليًا — نفس الحسابات (BKR / Jihad) ونفس كلمة السر.

---

## 3) أي تحديث مستقبلي = أمر واحد

عندما تُعدَّل الملفات لاحقًا (ميزات جديدة، إصلاحات)، كل ما عليك:

```bash
npm run cf:deploy
```

---

## 4) النسخ الاحتياطي — مهم لبياناتك

خذ نسخة احتياطية دورية من قاعدة السحابة:

```bash
npm run cf:backup
```

ينتج ملف `backup.sql` في مجلد المشروع — احتفظ به في مكان آمن.
لاستعادة نسخة احتياطية:

```bash
npx wrangler d1 execute kbi-db --remote --file=backup.sql
```

---

## 5) التشغيل المحلي على حاسوبك (اختياري)

- **وضع التطوير العادي** (SQLite كملف `db/custom.db` كما هو، بنفس بياناتك):

```bash
npm run dev
```

ثم افتح `http://localhost:3000`

- **تجربة نسخة السحابة محليًا قبل النشر** (Worker + D1 محلي):

```bash
npm run cf:d1-schema-local
npm run cf:d1-data-local
npm run cf:preview
```

ثم افتح `http://localhost:8787`

> بيانات المعاينة المحلية منفصلة تمامًا عن بيانات السحابة الحقيقية.

## 6) استكشاف الأخطاء

| المشكلة | الحل |
|---|---|
| `wrangler login` لم يفتح المتصفح | انسخ الرابط الظاهر والصقه في المتصفح يدويًا |
| `database_id is invalid` عند النشر | لم تُلصق المعرّف الصحيح في `wrangler.jsonc` — أعد الخطوة 3 |
| `Authentication error [code: 10000]` | سجّل الدخول مجددًا: `npx wrangler login` |
| `npm install` فشل | تأكد من إصدار Node (20+) ثم احذف مجلد `node_modules` وأعد الأمر |
| الموقع يفتح لكن لا تظهر بيانات | تأكد من تنفيذ الخطوتين 4 و 5 (إنشاء الجداول + نقل البيانات) |
| `There doesn't seem to be a D1 database with the name 'kbi-db'` | لم تُنشئ القاعدة بعد — نفّذ الخطوة 3 |

لعرض سجلات الخادم الحية بعد النشر:

```bash
npx wrangler tail
```

## 7) ملاحظات مهمة

- **قاعدة البيانات على السحابة منفصلة تمامًا** عن الملف المحلي `db/custom.db` —
  ما تضيفه محليًا لا يظهر على السحابة إلا بتصديره واستيراده، والعكس صحيح.
- **حسابات المديرين وكلمة السر** موجودة في `src/lib/auth.ts` (ثابت
  `ADMIN_PASSWORD`) — إن أردت تغييرها عدّل القيمة ثم `npm run cf:deploy`.
- الخطة المجانية في Cloudflare تكفي موقع نادٍ بشكل مريح جدًا
  (100,000 طلب يوميًا و5 GB لقاعدة D1).
- يمكن ربط نطاق خاص لاحقًا من لوحة Cloudflare:
  Workers & Pages ← kbi-club ← Settings ← Domains & Routes.
- ملف `d1/data.sql` يُحدَّث من بياناتك المحلية عند الحاجة عبر
  `node scripts/export-data.mjs` (بيئة لينكس/ماك).
